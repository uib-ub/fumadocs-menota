# Ch. 12. Names

Version 3.0 (12 December 2019)

This version of the chapter has been superseded by [version 3.1](/handbook/v3/HB3_ch12) (12 October 2022)

by Karl G. Johansson and Marco Bianchi

## 12.1 Introduction [#sec12.1]

Medieval manuscripts contain an abundance of names: personal names for historical,
fictional and mythological beings, place names relating to historical as well as to
mythological locations, animal names for domestic, wild and mythological creatures,
and artefact names for weapons, ships, buildings, etc. In the following, the encoding
of names is presented according to the recommendations in the TEI P5
Guidelines, [ch. 13](http://www.tei-c.org/release/doc/tei-p5-doc/en/html/ND.html).

The basic element for encoding names of any type is <E>name</E>, supplied with the
<Att>type</Att> and <Att>ref</Att> attributes.

<div className="table-xml-elements">
| Elements & attributes | Obl/Opt | Explanation |
|-----|-----|-----|
| <E>name</E> |  | Contains a name, i.e. a proper noun or a noun phrase. |
| <Att>type</Att> | Optional | Indicates what type of name it is. |
| <Att>ref</Att> | Optional | Identifier(s), i.e. xml:id(s) and/or external URI(s). |
</div>


Some examples from Old Norse sources:
```xml
<name>Egill Skalla-Grímsson</name>
<name>Borg</name>
<name>Sleipnir</name>
<name>Skiðblaðnir</name>
```


A distinction may be drawn between e.g. personal names, place names, animal names and
artefact names by using the <Att>type</Att> attribute:
```xml
<name type="person">Egill Skalla-Grímsson</name>
<name type="place">Borg</name>
<name type="animal">Sleipnir</name>
<name type="artefact">Skiðblaðnir</name>
```


For many encoders, the <E>name</E> element is all that is needed for a simple
identification of names in the text. The <Att>type</Att> attribute may be added
simultaneously or at a later stage.

For a more detailed encoding of personal names and place names, we recommend using
the elements <E>persName</E> and <E>placeName</E> respectively. They should be
treated as strictly equivalent with the <E>name</E> element and the <Att>type</Att>
attribute with the values `"person"{:js}` and `"place"{:js}`. 

Thus, ...
```xml
<name type="person">Egill Skalla-Grímsson</name>
```


... is equivalent to ...
```xml
<persName>Egill Skalla-Grímsson</persName>
```


... and ...
```xml
<name type="place">Borg</name>
```


... is equivalent to...
```xml
<placeName>Borg</placeName>
```


The element <E>persName</E> can contain several other elements and can thus be used
for a more detailed name analysis, e.g. for making a distinction between forenames,
patronymica and surnames. This level of detail is recommended in the header (cf. [ch. 14](/handbook/v3/HB3_ch14)), and will also be necessary for any encoding
of a text which should make the basis for a name index. In a similar way, the element
<E>placeName</E> can contain elements for various types of geographical
locations. For both elements, TEI P5 Guidelines offers an additional tagset, which will be
discussed and exemplified below.

Usually, XML elements for different types of names are used instead of
<E>w</E> elements. Under certain circumstances, however, it is convenient to use both
in combination. This is especially the case in linguistically annotated
transcriptions (cf. [ch. 11](/handbook/v3/HB3_ch11));  for an example of
a transcription of this type, see [ch. 15.4.5](/handbook/v3/HB3_ch15#sec15.4.5)).

## 12.2 Personal names [#sec12.2]

Personal names may be divided into several categories, depending on the source and
the naming conventions of the time.

<div className="table-xml-elements">
| Elements & attributes | Obl/Opt | Explanation |
|-----|-----|-----|
| <E>persName</E> |  | The name of a person, consisting of one or more words. |
| <Att>type</Att> | Optional | Indicates the type of name. Suggested values: `"historical"{:js}`, `"mythological"{:js}`.  |
| <Att>ref</Att> | Optional | Identifier(s), i.e. xml:id(s) and/or external URI(s). |
| <E>forename</E> |  | The first name of a person. |
| <E>addName</E> |  | An additional name of a person. |
| <Att>type</Att> | Optional | Indicates the type of name. Suggested values: `"epithet"{:js}`, `"metronym"{:js}`, `"mythological"{:js}`, `"nickname"{:js}`, `"patronym"{:js}`. |
| <E>surname</E> |  | The family name of a person, excluding patronyms and metronyms. |
| <E>roleName</E> |  | The name for a role held by a person. |
| <Att>type</Att> | Optional | Indicates the role of the person, e.g. in the form of a title. Suggested value: `"political"{:js}`. |
</div>


### 12.2.1 Forenames and patronymica [#sec12.2.1]

Forenames are encoded with the element <E>forename</E> contained in the
<E>persName</E> element:
```xml
<persName>
  <forename>Egill</forename>
</persName>
```


We recommend that patronymica, i.e. a father’s name such as Haraldsson or
Haraldsdóttir, should be encoded with the element <E>addName</E> and the
<Att>type</Att> attribute set to `"patronym"{:js}`:
```xml
<persName>
  <forename>Egill</forename>
  <addName type="patronym">Skalla-Grímsson</addName>
</persName>
```


Note that the patronym Skalla-Grímsson is often spelt without a hyphen,
Skallagrímsson.

It could probably be questioned whether Egill Skalla-Grímsson should be considered
a historical or a fictional person when he appears in _Egils saga
Skalla-Grímssonar_. The <Att>type</Att> attribute might be used to
specify this:
```xml
<persName type="historical">
  <forename>Egill</forename>
  <addName type="patronym">Skalla-Grímsson</addName>
</persName>
```


Mythological and legendary names could be seen as forming a group, once again
using the <Att>type</Att> attribute to establish the category. This example is
found in the _Poetic Edda_:
```xml
<persName type="mythological">
  <forename>Loki</forename>
  <addName type="metronym">Laufeyjarson</addName>
</persName>
```


As Loki has the second name from his mother Laufey, the value of the attribute is
`"metronym"{:js}` (meaning that it is derived from the name of the person’s
mother).

### 12.2.2 Surnames [#sec12.2.2]

In the Scandinavian and Old Icelandic material, surnames were introduced in the
14th and 15th centuries, in most cases for people belonging to the elite. These
names could be encoded with the <E>surname</E> element:
```xml
<persName>
  <forename>Bengt</forename>
  <addName type="patronym">Jönsson</addName>
  <surname>Oxenstierna</surname>
</persName>
```


### 12.2.3 Nicknames, Epithets and Titles [#sec12.2.3]

Medieval texts contain an abundancy of nicknames, epithets and titles. With the
additional tagset these could be treated in the same manner as forenames and
surnames, with the elements <E>addName</E> and <E>roleName</E>. In
_Egils saga Skalla-Grímssonar_, a man named Þorgils gjallandi ‘the
screaming’ appears. His nickname might be encoded as a type of
<E>addName</E>:
```xml
<persName>
  <forename>Þorgils</forename>
  <addName type="nickname">gjallandi</addName>
</persName>
```


Epithets indicating the providence of a person should also be encoded with the
<E>addName</E> element, specified by the <Att>type</Att> attribute. Thus,
Eyvindr austmaðr Bjarnarson in _Njáls saga_ has “austmaðr” as an
epithet and “Bjarnarson” as his patronym:
```xml
<persName>
  <forename>Eyvindr</forename>
  <addName type="epithet">austmaðr</addName>
  <addName type="patronym">Bjarnarson</addName>
</persName>
```


Titles such as “konungr”, “jarl” and “hersir” could be encoded by
using the <E>roleName</E> element in addition to the <E>addName</E>
element:
```xml
<persName>
  <forename>Óláfr</forename>
  <roleName type="political">konungr</roleName>
  <addName type="patronym">Tryggvason</addName>
</persName>
```


The <Att>type</Att> attribute indicates that the title is considered to refer to
the political system of the Old Norwegian society.

### 12.2.4 Sorting names [#sec12.2.4]

If an index is generated from the XML transcription, it might be useful to add
information on how to alphabetise names consisting of several elements. This is
achieved with the <Att>sort</Att>-attribute and numeric values.
```xml
<persName>
  <forename sort="2">Bengt</forename>
  <addName sort="3" type="patronym">Jönsson</addName>
  <surname sort="1">Oxenstierna</surname>
</persName>
```


### 12.2.5 Identifying historical individuals [#sec12.2.5]

The <Att>xml:id</Att> attribute could be used to link the occurrence of a name to the
individual it denotes, either internally or externally. 

#### 12.2.5.1 Internal referencing [#sec12.2.5.1]

Biographical data can be stored in the header of the XML file. The unique
<Att>xml:id</Att> defined for each biographical entry could then be used to link
occurrences of a name to it.
```xml
<profileDesc>
  <particDesc>
    <listPerson type="historical">
      <person xml:id="Njall">
        <persName>
          <forename>Njáll</forename>
          <addName type=”patronym”>Þorgeirsson</addName>
        </persName>
      </person>
      <person xml:id="...">
        . . .
      </person>
    </listperson>
  </particDesc>
</profileDesc>
```


The corresponding markup in the body of the XML file would then be:
```xml
<persName xml:id="#Njall">
  <forename>Njáll</forename>
</persName>
```


See the TEI P5 Guidelines, [ch. 13.3](https://www.tei-c.org/release/doc/tei-p5-doc/en/html/ND.html#NDPERS), for an extensive description of biographical data.

#### 12.2.5.2 External referencing [#sec12.2.5.2]

References to external biographical resources can be put either into the header
or directly into the transcription. The following two solutions both link the
Njáll’s name to his Wikidata entry:
```xml
<!-- HEADER -->
  <person xml:id="Njall https://www.wikidata.org/wiki/Q2642621">
<!-- BODY -->
  <persName xml:id="#Njall">
    <forename>Njáll</forename>
  </persName>
```


Or, without internal reference to the header:
```xml
<persName xml:id="https://www.wikidata.org/wiki/Q2642621">
  <forename>Njáll</forename>
</persName>
```


See [ch. 15.4.5](/handbook/v3/HB3_ch15#sec15.4.5) for suggested external
resources and more examples, and also [ch. 14.3.6](/handbook/v3/HB3_ch14#sec14.3.6).

## 12.3 Place names [#sec12.3]

The encoding of place names should be rather straight-forward, but there are a few
things that need to be mentioned and exemplified. The starting point is the
above-mentioned encoding of all place names with the element <E>name</E> and an
attribute <Att>type</Att> with the value `"place"{:js}`:
```xml
<name type="place">Borg</name>
```


A more detailed encoding is achieved by the additional tagset. We recommend that this
tagset is used in cases when place names are to be more thoroughly encoded:

<div className="table-xml-elements">
| Elements | Explanation |
|-----|-----|
| <E>placeName</E> | A name of a specific location. |
| <E>settlement</E> | The name of the smallest component of a place name expressed as a hierarchy of geo-political or administrative units. |
| <E>region</E> | Larger or administratively superior to the settlement and smaller or administratively less important than the country. |
| <E>country</E> | Larger or administratively superior to the region. |
</div>


All of the above mentioned elements can be linked to the place they denote by means
of a <Att>ref</Att>-attribute with identifiers, i.e. xml:ids or external URIs.

The additional element <E>settlement</E> adds information about administrative
units, i.e. farms, villages or cities. In this example, we have chosen Skara, one of
the oldest cities of modern-day Sweden:
```xml
<placeName>
  <settlement>Skara</settlement>
</placeName>
```


A region is a larger administrative unit than the district or settlement, as e.g. the
province of Västergötland, in the medieval material referred to as “Vestra
Gautland”:
```xml
<placeName>
  <region>Vestra Gautland</region>
</placeName>
```


The region of Västergötland forms a part of the country referred to as Svíþjóð in
medieval texts:
```xml
<placeName>
  <country>Svíþjóð</country>
</placeName>
```


### 12.3.1 Identifying places [#sec12.3.1]

Similar to personal names, attestations of place names can be linked to authority
records describing the place itself with a <Att>ref</Att> attribute. See [ch. 15.4.6](/handbook/v3/HB3_ch15#sec15.4.6) below and the TEI P5 Guidelines, 
[ch. 13.3.4](https://www.tei-c.org/release/doc/tei-p5-doc/en/html/ND.html#NDGEOG).

## 12.4 Other names [#sec12.4]

There are other groups of names that might be singled out in the encoding. In the
following, we present suggestions as to how animal names and names of artefacts could
be treated. The <Att>type</Att> attribute is used liberally to enhance
searchability.

### 12.4.1 Animal names [#sec12.4.1]

Medieval texts contain names for horses, dogs and other domestic animals. These
could be encoded with the <E>name</E> element and the <Att>type</Att>
attribute. On a basic level we would suggest that all animal names are marked with
the attribute value `"animal"{:js}`:
```xml
<name type="animal">Freyfaxi</name>
```


It should also be possible to give more specific information in the
<Att>type</Att> attribute. The name “Freyfaxi” might be specified as
the name of a horse:
```xml
<name type="horse">Freyfaxi</name>
```


There are also names of animals in relation to myths and legends. For example,
Sigurðr Fáfnisbani had a horse named Grani. If we wish to encode a mythological or
legendary name this could be done by specifying the value `"horse"{:js}` of the
<Att>type</Att> attribute, and `"legendary"{:js}` in a <Att>subtype</Att>
attribute:
```xml
<name type="horse" subtype="legendary">Grani</name>
```


There is no element <E>animalName</E> on par with <E>persName</E> and
<E>placeName</E>. For all but the most detailed encodings, we suggest that
the type value `"animal"{:js}` is sufficient.

### 12.4.2 Artefact names [#sec12.4.2]

There are a number of names for artefacts in the medieval material, e.g. for
weapons and ships. These names could be encoded in the same fashion as the ones
described above. The ship belonging to the god Freyr in _Snorra Edda_
could then be encoded as follows:
```xml
<name type="artefact">Skiðblaðnir</name>
```


This artefact could be specified as a ship:
```xml
<name type="ship">Skiðblaðnir</name>
```


And it could further be encoded as a mythological name:
```xml
<name type="ship" subtype="mythological">Skiðblaðnir</name>
```


In most cases, we believe that the attribute value `"artefact"{:js}` is
sufficient. However, if a text contains many object names it might be convenient to
use the element <E>objectName</E> for a more clear-cut distinction between names
of artefacts and other types of names. 

Similar to personal names and place names, objects’ names can be linked to the objects they denote by means of a
<Att>ref</Att> attribute with identifiers pointing to an internal registry or
an external resource, i.e. xml:ids or external URIs.
