# Appendix H: Stylesheets (XSL and CSS) for the handbook

Version 3.0 (12 December 2019)

by Marco Bianchi

## H.1 Introduction [#secH.1]

Version 3 of the Menota handbook is transformed to html with the stylesheet
handbook_v3.xsl. The stylesheet outputs clean box-based html5. Generally, all
`@rend{:sh}` are converted to html classes. All styling is taken care of by
menota_handbook_3.css.

## H.2 The HTML [#secH.2]

handbook_v3.xls produces clean html5 without any form styling in html code. The
html skeleton:
```xml
<!DOCTYPE html>
<html>
  <head>
  </head>
  <body>
    <div id="page">
      <div id="main-wrapper">
        <div id="header-wrapper">
          <header> </header>
          <nav> Site-navigation</nav>
        </div>
        <div id="content-wrapper">
          <section id="sidebar" role="navigation">Page-MENU</section>
          <main id="content">
            <article>HANDBOOK ENTRIES</article>
          </main>
        </div>
      </div>
      <footer></footer>
    </div>
  </body>
</html>
```


## H.3 The CSS [#secH.3]

The css sheets use css3 but should degrade gracefully in non-compliant browsers. The
main typeface for handbook v3 is Andron, which is read in with css
`@font-face{:sh}` and thus does not need to be installed on users’ computers.
`@font-face{:sh}` is supported in all major modern browsers. Non compliant
browsers will display a serif-font. 

Handbook v3 uses one css sheet: menota_handbook_3.css

Breaking points for small screens are set at 960px (width of header items and main
content 100%) and 450px in portrait mode (larger main font-size).

### H.4.3 Generic values for `@rend{:sh}` [#secH.4.3]

for `@rend{:sh}`:

- `"blue"{:js}` (blue font color)
- `"bold"{:js}` (bold style)
- `"code"{:js}` (monospace font)
- `"red"{:js}` (red font color)

## H.5 Styling tables [#secH.5]

Tables are structured according to the following pattern in html:
```xml
<table>
  <colgroup>
    <col style="width20">
    <col style="width80">
  </colgroup>
  <thead>
    <tr>
      <th></th>
      <th></th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td></td>
      <td></td>
    </tr>
  </tbody>
</table>
```


The <E>colgroup</E> element is created dynamically if the first row contains cells
with the attribute `@rend{:sh}`. This means that the column widths of the
html table can be controlled with the attribute `@rend{:sh}` in the cells of the
first table row. Below is the xml code of the html table above:
```xml
<table>
  <row rend="label">
    <cell rend="width20"></cell>
    <cell rend="width80"></cell>
  </row>
  <row>
    <cell></cell>
    <cell></cell>
  </row>
</table>
```


### H.5.1 Styling tables with explanations of xml-elements [#secH.5.1]

A table with explanations of xml-elements and their attributes ([such as H.4.1 above](#tab.1)) can be given
`@rend{:sh}`=`"xml-elements"{:js}` in the <E>table</E> element. The
xls stylesheet tries to wrap all rows with a <E>gi</E> or a tag in
the first cell into a <E>tbody</E> element together with the following rows.
Such tables must adhere to the following principles: 

- The <E>table</E> tag must have a `@rend{:sh}` with the value `"xml-elements"{:js}`
- The first cell of the first row in each block must contain a <E>gi</E> or a <E>tag</E> element
- The first cells of all other rows in a block must not contain any <E>gi</E> element (otherwise, the respective row will be treated as the first row in a block)

Strings marked with <E>att</E> and <E>val</E> in the first cell of each row
are indented automatically.

### H.5.2 Styling glyph tables [#secH.5.2]

Tables with explanations of abbreviations and other glyphs can be marked upp with
table rend="abbr". In such tables, cells containing a tag hi
rend="glyph" (and nothing else) are rendered differently.

## H.6 Styling images [#secH.6]

An image and its caption should be structured as follows:
```xml
<figure rend="leftalign width33">
  <graphic url="path/to/image.jpg" />
  <figDesc n="1.2">Figure Caption</figDesc>
</figure>
```


The position and width of the image can be controlled with <E>rend</E> in the
wrapping <E>figure</E> element. By default, <E>figure</E> is displayed floating
to the left of the text at a width of 50% with a border around the containing
elements. The figure’s number should passed through `@n{:sh}` in <E>figDesc</E>.
The xslt adds automatically a figure label. The above <E>figDesc</E> will thus be
rendered as “Fig. 1.2: Figure Caption”.

If used without a wrapping <E>figure</E> element, images placed in a
<E>graphic</E> element are displayed at their original size without any
border

## H.7 Styling code [#secH.7]

Block level code elements are wrapped into a html <E>pre</E> tag that preserves
line breaks, white spaces and indentations. Such elements should thus not follow the
indentation of surrounding xml. The following coding of a CDATA section with
surrounding xml ...
```xml
<p>Some text before the code</p>
  <egXML><![CDATA[<figure rend="leftalign width33">
   <graphic url="path/to/image.jpg"/>
   <figDesc n="1.2">Figure Caption</figDesc>
   </figure>]]>
  </egXML>
<p>Some text after the code</p>
```


... will be output as:
```xml
<figure rend="leftalign width33">
  <graphic url="path/to/image.jpg" />
  <figDesc n="1.2">Figure Caption</figDesc>
</figure>
```


By default, code within <E>eg</E>, <E>egXML</E> and <E>code</E> is displayed as
a block element. With `@rend{:sh}`=`"inline"{:js}` it can be forced to be
treated as an inline element. Alternatively, the markup `&lt;hi
rend="code"&gt;` or <E>tag</E> may be used for inline code.

Xml elements, attributes and values should be tagged with their respective semantic
markup: <E>gi</E>, <E>att</E> and <E>val</E>.
