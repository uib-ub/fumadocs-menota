Contents

This list includes a large selection of characters for the transcription and display of medieval Nordic texts. It is divided into two main sections:

1. Characters needed for the transcription (and hence display) of medieval Nordic sources. These characters are those actually found in the primary sources themselves.

2. Characters that are not found in the primary sources, but are needed for the display of transcribed text. These characters are used to show unclear readings, metrical analysis and text critical information (on matters suchs as editorial additions, deletions and emendations).

 

Basic and composite characters

The bulk of characters are base line characters, either simple (such as "a") or composite (such as "á"). A large number of composite characters are included in the Unicode Standard, but new composite characters are not likely to be accepted. Unicode recommends that these characters are encoded and displayed as a combination of a base line character and a combining diacritical mark. This applies to e.g. "o ogonek with acute accent" (a glyph for this character is located here).

By analogy, this principle also applies to composite characters which in fact are included in the Unicode standard, such as "á". For this reason, alternative encodings are given for a large number of characters in this list. These alternatives are strictly equivalent, and they are identical to the ones found in the Unicode Standard. For example, the character "á" can be encoded with the entity "&aacute;" and displayed with reference to the Unicode character 00E1 in the code chart Latin-1 Supplement. Alternatively, it can be encoded as a sequence of "a" and the entity "&combacute;", referring to the Unicode characters 0061 in Basic Latin and 0301 in Combining Diacritical Marks. In both cases, the correct glyph, "á", will be displayed.

 

Entities

Although the full Unicode Standard is supported by XML, we recommend using entities for the encoding of all characters outside Basic Latin (US ASCII) and especially for characters located in the Private Use Area. Entities are named according to the rules set out in ch. 5 and ch. 6, and are - as far as possible - ISO conformant (cf. ch. 2.2.2).

 

Characters in the Private Use Area of the Unicode Standard

The present list contains Unicode codepoints for those characters that are defined in Unicode 4.0. Characters outside the present Unicode Standard have been allocated code points in the Private Use Area. This area is part of the Unicode Standard, but the allocation of characters to code points in this area is left to individual users or user groups (such as Menota). For practical purposes, the code points and descriptive names of characters in the Private Use Area are shown in bold type (and dark blue) in the present list.

Characters in the official part of the Unicode Standard will be displayed correctly with any large Unicode font. Characters in the Private Use Area require a specialised font. Several fonts of this type are now available, cf. the font page. The fonts referred to here contain all necessary characters, so a single font will suffice for the whole set of characters.

 

Coordination with the Medieval Unicode Font Initiative (MUFI)

The allocation of characters in the Private Use Area has been coordinated with the MUFI character recommendation v. 1.0.

For further information and links to the MUFI character recommendation, cf. the Medieval Unicode Font Initiative site.

Note that the MUFI recommendation has an even longer list of characters, so characters missing in the present list may actually be found in this recommendation. Also note that Menota's DTD contains all characters of the MUFI character recommendation v. 1.0.

The present list has characters in alphabetical order (within each group) in order to facilitate browsing. Characters in the MUFI character recommendation are listed in code chart sequence, which may look a little bewildering at first. However, since the recommendation is a PDF file readers will find the search routines in an application like Acrobat Reader very helpful.

2. Characters needed for display only

 

2.1 Unclear characters

Back to overview

We recommend that characters that are difficult to read are encoded with the <unclear> element. In text display such characters are usually shown with a dot below. Since in principle all characters can be difficult to read, the number of possible combinations is very high. It is therefore recommended that the combining dot below is used in display. Note, however, that no less than 38 composite characters with dot below are included in the range Latin Extended Additional.
